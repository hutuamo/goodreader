# GoodReader V1 规格

## 1. 产品目标

GoodReader 是一个仅面向 macOS 的本地桌面阅读工具。它把本地 PDF、静态 HTML 目录和公开在线链接转换为符合接入契约的 HTML 书籍包，集中到一个类似微信读书书架的入口中，并在应用内 WebView 中提供统一的阅读进度、高亮、笔记和书签。

当前版本的成功标准不是兼容任意网站或电子书格式，而是建立一条可靠的闭环：预检来源、确认结构、在后台生成契约化书籍包、完成安全与质量校验、一次性进入书架，并支持完整阅读与标注。

## 2. V1 范围

### 包含

- macOS Apple Silicon 桌面应用与单一主窗口。
- 类微信读书的本地书架网格。
- 契约化 HTML 书籍包扫描、校验与统一 HTTP 托管。
- 从数字 PDF、现有静态 HTML 目录和公开在线链接生成书籍，来源保持不变。
- 对非中文来源可调用本机 Agent 翻译为简体中文，并可选保留正文块级原文。
- 持久化生成任务、全局单任务队列、暂停、继续、取消和失败后切换 Agent。
- 书名与作者搜索。
- 最后阅读位置与书架进度展示。
- 高亮、笔记、书签及统一标注侧栏。
- 阅读界面跟随系统外观，并可手动切换明亮或黑暗模式。
- 可选的逐正文块对照文本。
- SQLite 持久化、自动备份和整库恢复。
- 将 `RustForDummies` 单独迁移为第一本本地验收书。
- arm64、ad-hoc 签名的 `.app` 与 `.dmg`。

### 不包含

- Windows、Linux、多窗口和多人使用。
- 账号、云同步、跨设备同步或社交能力。
- 扫描 PDF 的 OCR；EPUB、Markdown、Word 的直接阅读或转换。
- 跨书正文搜索。
- 全局字体、行距或统一正文排版。
- 书架分组、手工排序、拖拽导入和自动更新。
- 任意书籍脚本执行、导入时自动翻译 JavaScript。
- 内容指纹与书籍修改检测。
- 旧版 `RustForDummies` 标注迁移。
- Developer ID、公证、Universal Binary 或公开分发。

## 3. 桌面架构

- Tauri 2 管理 macOS `.app`、单一系统 WebView 和应用生命周期。
- Rust 进程内服务负责书籍扫描、契约与安全校验、静态文件托管、阅读状态接口、SQLite 与备份。
- 书架和统一阅读器使用原生 HTML、CSS 与少量 TypeScript；Vite 只参与构建。
- 正式应用每次启动时绑定 `127.0.0.1` 的随机空闲端口。
- WebView 通过一次性凭证换取仅本次运行有效的会话；写接口校验会话、来源与内容类型，不开放 CORS。
- 应用退出时停止 HTTP 服务并使会话失效。
- 互联网外链交给系统默认浏览器，书内导航保留在应用窗口。

## 4. 用户数据目录

```text
~/Library/Application Support/GoodReader/
├── Books/
│   ├── <任意目录名>/
│   │   └── book.json
│   └── ...
├── Backups/
└── goodreader.sqlite3
```

- 首次启动自动创建所需目录。
- 书架提供“在 Finder 中打开书库”和“重新扫描”。
- `Books/` 的每个直接子目录是一份候选书籍包；不递归发现嵌套书籍。
- 应用内导入先写入隐藏的临时目录，通过完整契约校验后再原子移动为正式书籍目录。
- `.app` 内不保存或修改书籍与阅读状态。
- 开发模式可以覆盖数据目录，正式版本始终使用 Application Support。

## 5. 静态书籍包

### 5.1 建议目录

```text
rust-for-dummies/
├── book.json
├── cover.jpg
├── site/
│   ├── index.html
│   ├── assets/
│   └── chapters/
└── parallel/
    └── <chapter-id>.json
```

目录名不参与身份判断，可以重命名或移动。

### 5.2 `book.json`

`book.json` 必须全小写，并且是导入完成后身份、展示信息、入口和章节顺序的唯一权威来源。转换导入可以从 HTML 推断初始展示信息，但必须先生成 `book.json` 才能进入书架。

```json
{
  "schemaVersion": 1,
  "id": "b1739d0e-35a8-4ae4-b618-907bf42c4d37",
  "title": "Rust 大全",
  "originalTitle": "Rust All-in-One For Dummies",
  "author": "Paul McFedries",
  "language": "zh-CN",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "cover": "cover.jpg",
  "entry": "site/index.html",
  "chapters": [
    {
      "id": "introduction",
      "title": "引言",
      "path": "site/chapters/introduction.html",
      "parallelText": "parallel/introduction.json"
    },
    {
      "id": "book1-ch1",
      "title": "第 1 章：认识 Rust",
      "path": "site/chapters/book1-ch1.html"
    }
  ]
}
```

约束：

- `schemaVersion`、`id`、`title`、`author`、`cover`、`entry`、`chapters` 必填。
- `originalTitle`、`language`、`sourceLanguage`、`targetLanguage` 可选；语言字段使用标准语言代码。翻译书籍记录中文正文、来源语言与目标语言，未翻译书籍不伪造译名。
- `id` 是创建时生成且永久不变的 UUID；书名允许重复。
- 章节数组顺序就是标准阅读顺序。
- 章节 ID 在一本书内唯一且长期稳定，标题可以修改。
- `entry` 是书籍首页，不计入阅读进度，也不提供正文标注。
- `parallelText` 可选，只能指向包内 JSON。
- 所有路径必须是包内相对路径，不能越过包根目录或通过符号链接逃逸。

### 5.3 HTML 接入契约

每个章节页面必须明确声明章节和主正文：

```html
<main data-goodreader-content data-goodreader-chapter="book1-ch1">
  <p data-goodreader-block="book1-ch1-ownership-intro">
    所有权是 Rust 最独特的特性之一……
  </p>
</main>
```

- 每个可标注正文块必须有 `data-goodreader-block`。
- Block ID 在整本书内唯一、长期稳定且删除后不得复用。
- 只有 `data-goodreader-content` 内的标记正文块参与进度和标注。
- 导航、页头、页脚和页面装饰不参与。
- 单次文字选择只能位于一个正文块内；跨块选择不给予标注操作。

### 5.4 对照文本

对照文本文件是不可执行 JSON，以 Block ID 映射只读纯文本：

```json
{
  "schemaVersion": 1,
  "language": "en",
  "blocks": {
    "book1-ch1-ownership-intro": "Ownership is one of Rust's most unique features..."
  }
}
```

- GoodReader 负责显示与隐藏对照文本。
- 对照文本不参与进度，也不能高亮、写笔记或添加书签。
- JSON 内容作为文本渲染，不能解释为 HTML 或脚本。

## 6. 脚本与安全边界

- 书籍包不得运行自带 JavaScript。
- 目录导入会移除自带脚本、行内事件、主动嵌入、表单与外部主动资源，并由 GoodReader 注入统一阅读脚本。
- V1 不翻译任意 JavaScript 的业务语义；依赖脚本生成正文或专有交互的书籍需要在制书阶段先转为静态 HTML。
- 通用阅读行为迁入 GoodReader；纯内容数据改为 HTML、JSON 或受支持的声明式配置。
- 转换完成后的契约校验拒绝残留脚本标签、内联事件、`javascript:` URL、可执行 SVG、嵌入页面和未经允许的网络资源。
- 路径校验阻止目录穿越和符号链接逃逸。
- 服务端为书籍响应设置严格 CSP，并只注入 GoodReader 发布的版本化阅读脚本。
- 安全校验与 CSP 是互补防线；V1 不宣称已具备未知发布者身份验证。

## 7. 发现、冲突与移除

- 启动时扫描一次，点击“重新扫描”时再次扫描；V1 不监听文件系统变化。
- 缺少或无法解析 `book.json`、路径不存在、契约不完整或安全校验失败时，候选包不进入书架。
- 无效包进入“导入问题”区域，显示明确原因和目录位置；其他有效书不受影响。
- 多个目录声明相同 UUID 时构成导入冲突，所有冲突副本都停止加载，不按时间或目录顺序猜测赢家。
- “删除书籍副本”只允许操作 `Books/` 的直接子目录，并将目录移到 macOS 废纸篓；原始导入目录与 SQLite 阅读状态均不受影响。
- 移走目录只让书从书架消失，SQLite 阅读状态继续保留；相同 UUID 再次出现时自动恢复。
- “永久忘记”只删除该 UUID 的阅读状态，不删除磁盘上的书籍包；执行前显示标注数量并二次确认。
- V1 约定书籍内容不可变，但不计算内容指纹，也不检查外部修改。

## 8. 阅读进度

- 阅读进度表示最后阅读位置，不表示曾经到达的最远位置；回到前文退出后进度可以回退。
- 未开始阅读时，点击封面打开 `entry`。
- 已开始阅读时，点击封面恢复到最后章节与正文位置。
- 卡片菜单提供“打开书籍首页”。
- 进度按章节等权近似计算：

```text
(当前章节从 0 开始的序号 + 当前章节正文滚动比例) / 章节总数
```

- `entry` 不计入进度；到达最后一章底部显示“已读完”。
- 书架卡片显示“未开始”、`百分比 · 当前章节` 或“已读完”。

## 9. 阅读标注

### 9.1 共同锚点

- 高亮、笔记和书签都必须锚定单个正文块内的一段选中文字。
- 持久化位置包含书籍 ID、章节 ID、Block ID、块内起止位置和选中文字。
- 标注只写入 SQLite，不修改书籍文件。
- 书籍内容按契约不可变，因此 V1 不实现模糊重定位或失效标注流程。

### 9.2 类型

- 高亮：明黄、青绿、天蓝、粉红四种固定颜色，默认并记住上次选择；V1 不提供事后改色。
- 笔记：一段选中文字对应至多一条可编辑个人文字。
- 书签：选中文字本身是返回锚点，同一选区至多一个书签。

### 9.3 重叠规则

- 同一选区可以同时拥有一个高亮、一个笔记和一个书签，三者独立删除。
- 两个高亮不能发生范围重叠，也不自动合并相邻高亮。
- 同一选区重复添加书签不产生新记录；重复添加笔记打开原笔记编辑。
- 笔记或书签可以与高亮部分重叠。

### 9.4 创建与管理

- 单块文字选择完成后自动显示浮动工具条：复制、四色高亮、书签、笔记，以及存在时的对照原文。
- 对照原文入口使用地球仪图标并始终显示；当前正文块没有对照原文时置灰且不可点击，有原文时显示正文块级原文。原文浮窗不显示语言缩写，并在焦点移出或点击外部时自动关闭。
- 点击空白处或按 `Esc` 关闭；普通右键继续使用系统菜单。
- 统一侧栏包含“目录”和“标注”两个主标签。
- 标注页默认按创建时间倒序混合显示，并可筛选全部、高亮、笔记、书签。
- 点击标注跳回正文锚点；高亮和书签可删除，笔记可编辑或删除。

## 10. 书架体验

- 视觉参考微信读书网页书架：宽松顶部栏、搜索框、封面网格和克制留白，但不复制账号、会员、传书或移动版入口。
- 搜索只按书名和作者执行不区分大小写的包含匹配，不索引正文。
- 已阅读书按最后打开时间倒序排列。
- 未读书排在已阅读书之后，并按书名排序。
- 卡片显示封面、书名、作者和阅读进度。
- 工具栏与空书架都提供“导入书籍”，选择目录后显示转换结果与安全处理说明。
- 卡片菜单将“删除书籍副本”和“永久忘记阅读状态”分开，并分别解释可恢复性与数据影响。
- 正文继续使用书籍自己的 HTML 与 CSS；GoodReader 只叠加隔离样式的统一阅读控件和语义化明暗颜色映射，不提供全局排版设置。
- 阅读主题默认跟随 macOS；阅读栏提供明亮／黑暗切换，用户选择保存在 SQLite 中并应用于书籍首页、章节正文和统一控件。

## 11. SQLite 与备份

- `goodreader.sqlite3` 是阅读状态的唯一权威来源，不使用书籍页面 localStorage。
- 数据至少覆盖书籍身份关联、最后阅读位置、高亮、笔记、书签和界面偏好。
- 每天首次启动时创建一份 SQLite 一致性快照，数据库结构升级前额外备份。
- `Backups/` 只保留最近 7 份自动备份。
- 设置提供“立即备份”和“从备份恢复”。
- 恢复执行整库替换，不做逐条合并；恢复前先备份当前数据库并二次确认。
- 备份不包含书籍包。

## 12. `RustForDummies` 验收书

- 原书籍目录保持不变，例如 `/path/to/RustForDummies`。
- 在开发工作区生成独立的 GoodReader 兼容书籍包。
- 使用现有 `site/` HTML 与 CSS，补齐 `book.json`、稳定章节 ID 和全书唯一 Block ID。
- `.en.js` 转换为按 Block ID 对应的只读对照文本 JSON。
- 现有 `reader.js` 不进入书籍包；通用目录、进度、原文、高亮、笔记和书签由 GoodReader 接管。
- 原始 PDF、制书工具、交接文档和开发文件不进入包。
- 没有需要迁移的真实旧标注，因此不实现 `rustbook.v1` 导入器。
- 测试时把转换结果复制到 Application Support 的 `Books/`，最终 `.app` 与 `.dmg` 不内置书籍。

## 13. 交付与验收

### 13.1 功能验收

1. 空书架首次启动正常，能够从应用打开 Finder 书库目录。
2. 选择现有 HTML 目录后生成带新 UUID 的合法书籍包，原目录不变，卡片立即出现。
3. 重复 UUID 的两个包均不加载，移走一个后剩余包恢复。
4. 未读书进入书籍首页；读过后封面恢复最后位置，书架显示章节等权进度。
5. 四色高亮、笔记和文字书签可以创建、跳转、编辑或删除，并遵守单块和重叠规则。
6. 文字选择工具栏始终显示地球仪；仅当当前正文块具备对照原文时可点击，否则置灰。对照原文不参与标注和进度。
7. 应用退出重启后进度与全部标注完整恢复。
8. 删除书籍副本会移到废纸篓并保留状态，原始导入目录不变；永久忘记能单独清空阅读状态。
9. 自动备份、立即备份和整库恢复可验证。
10. 外部链接在默认浏览器打开，书内导航留在应用中。
11. 阅读界面能跟随系统外观并手动切换明亮／黑暗模式，重开书籍后保持用户选择。

### 13.2 安全验收

1. 服务只监听 `127.0.0.1` 的随机端口。
2. 无有效会话、来源不符、跨域或错误内容类型的写请求被拒绝。
3. 包内路径无法越过书籍根目录。
4. 自带脚本、行内事件、主动嵌入内容和未许可网络资源被拒绝或由 CSP 阻止。
5. GoodReader 只注入自身版本化阅读脚本。

### 13.3 桌面包验收

1. 生成 arm64、ad-hoc 签名 `.app` 与 `.dmg`。
2. DMG 可挂载，应用包结构、架构、Bundle ID 与签名状态可核验。
3. 从应用包启动后可完成扫描、阅读、持久化、备份和正常退出。
4. 替换应用本体不会删除 Application Support 中的书籍与阅读状态。

## 14. 实施顺序

1. 契约与校验器：冻结 `book.json`、HTML 与对照文本 schema，并用有效/无效最小书籍夹具验证。
2. Rust 核心：实现书籍扫描、冲突诊断、随机回环服务、会话校验、SQLite 与备份。
3. 书架：实现微信读书风格网格、搜索、排序、进度和管理入口。
4. 阅读运行时：实现注入、进度、浮动工具条、三类标注、侧栏和对照文本。
5. 样例迁移：转换 `RustForDummies`，逐章验证正文、样式、导航和对照文本。
6. 桌面封装：完成 Tauri 生命周期、外链处理、arm64 `.app`、DMG 与端到端验收。

本规格已由官家确认，作为 V1 实施与验收基线。
