# GoodReader 持有 Agent 任务并复用本机 CLI 运行时

## 状态

已接受。

## 背景

GoodReader 需要为书籍摘要、基于书籍的问答和书籍制作提供完整 AI 能力，但不应复制 Codex、Claude Code、Cursor Agent 等工具已经具备的账号认证、API 密钥、模型选择和供应商配置。不同 CLI 都能以本机进程执行任务，但其输入输出、会话恢复、权限控制和错误事件并不统一；如果把任务状态绑定到某一个 CLI 会话，用户将无法在同一任务中自由切换 Agent。

## 决策

GoodReader 将书籍 AI 工作区、共享历史、任务、检查点和版本化产物作为自身领域数据，并把本机 Agent CLI 视为可替换执行器。GoodReader 使用独立本地任务执行器和 Agent 适配器启动 CLI；Codex、Claude Code 与 Cursor Agent 使用内置适配器，用户也可以按最低通用契约添加其他 CLI。

同一本书的不同 Agent 共享完整协作历史。每次执行由 GoodReader 装配任务上下文包和隔离任务工作区；跨运行时切换创建新执行，不迁移 CLI 私有会话。标准文件契约是基础数据通道，本地全文检索工具提供多轮书籍检索，MCP 和结构化流属于可选增强能力。

GoodReader 不保存模型密钥或模型配置。Agent 只能在任务能力策略内读取指定输入和写入候选产物；正式书籍、阅读标注和书架变更仍由 GoodReader 校验并由用户确认。

## 结果

- 用户可以在同一任务中切换 Agent，同时保留任务历史和产物。
- GoodReader 需要维护持久任务状态、后台执行器、统一事件、上下文装配和适配器能力矩阵。
- 自定义 CLI 可以低门槛接入，但缺失流式、原生恢复或权限映射时会降级相应体验。
- 书籍问答不依赖嵌入模型或向量数据库，避免引入第二套 AI 配置。
- 本机 CLI 仍可能按自身配置调用远程模型；该决策提供本地编排和配置解耦，不等同于离线推理。
